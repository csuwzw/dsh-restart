# dsh-restart 1.0.2

修正「重启成功」判据：不再等旧实例的端口，改为按这次拉起的新实例判定。**升级前你会看到
`listening=False` 而误以为重启失败——其实每次都成功了。**

## 本次更新

- **判据重写。** 旧判据等的是**旧实例**的端口 `$Port` 重新进入 Listen，而桌面版 Host 固定以
  `--port 0` 启动、端口每次由系统分配（`dsh-desktop-host/lib/index.js` 的
  `args: ["--no-open", "--host", "127.0.0.1", "--port", "0"]`）。新实例几乎不可能拿到同一个
  端口，所以旧判据**结构上就是错的**：重启成功它也报 `listening=False`。

  新判据走三步：先找这次拉起的主进程（新进程树里唯一「父进程不在树内」的那个），再在它下面
  找命令行匹配 `dsh-desktop-host[\\/]lib[\\/]index\.js` 的 Host 子进程，看它有没有在监听。
  Host 与 `dsh-subprocess-local` 的 runner 子进程**进程名相同**，只能靠命令行区分。

- **日志格式随之改变。**

  ```
  旧：verify: port 19387 listening=False after 30s
  新：verify: main=65108 host=66888 listening=[63845] after 9s
  ```

  方括号里是新实例实际监听的端口（可能多个），与旧实例的 `port=` 不同属正常。

- **这个误报是真的、且长期存在。** 本插件仓库维护者机器上的真实日志：

  | 日期 | 端口 | 判据输出 |
  | --- | --- | --- |
  | 2026-10-17（固定端口时期） | 19387 | `listening=True after 9s`（4 次里 3 次 True） |
  | 2026-10-17 14:50 | 19387 | `listening=False after 30s`（首次误报） |
  | 2026-10-18 起（端口随机化后） | 54852 / 58311 / 54467 / 54079 | 全部 `listening=False after 30s` |
  | 2026-10-19 | 54205 / 57441 | 仍为 `False` |
  | 2026-10-19 04:14 | 51847 | `listening=True after 8s`（偶然：新实例复用了刚释放的旧端口） |

  而日志里的 `oldPid` 链条 `46676 → 49372 → 50340 → 50444 → 57124` 每次的下一个 `oldPid`
  就是上一次拉起的新实例 pid——**进程一直在正常换代，每次重启都真的成功了**，`False` 是误报。

  10-17 还能偶然报 `True`，是因为那几天端口固定为 19387；10-18 起端口变成随机的 5xxxx，
  判据立刻全变 `False`。

- **更正 1.0.1 发布说明里的一句错话。** 当时「已知边界」写着「真实桌面版始终使用固定端口」——
  错的，桌面版一直用 `--port 0`。已就地更正，并同步修正 1.0.0 的发布说明与验收记录。

- **同步整改文档。** README.md / README_EN.md 的亮点、日志示例、判读说明全部改为按新实例
  判定；`docs/releases/v1.0.0.md`、`docs/releases/v1.0.1.md`、
  `docs/verification/2026-10-17-v1.0.0.md` 里残留的旧判据文案与错误论断一并更正。

## 安装

```
set ELECTRON_RUN_AS_NODE=1
"C:\D\software\DeepSeek Harness\DeepSeek Harness.exe" --expose-internals ^
  "C:\D\software\DeepSeek Harness\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js" ^
  plugin --profile desktop add https://codeload.github.com/csuwzw/dsh-restart/tar.gz/refs/tags/v1.0.2
```

把路径换成自己的安装目录。其余安装方式（应用内插件管理器、手工放置、离线 tgz）见
[README](../../README.md#安装)。

**首次安装必须手动重启一次 DSH**——按钮要等重启后才存在。之后就用按钮本身。

## 升级与重启

从任何旧版本升上来，只需重新执行上面的安装命令，把 tag 换成 `v1.0.2`。

本版只改 `restart.ps1` 与文档，`index.js`、`client.js`、`cordis.patch.yml` 与 1.0.1 逐字节相同，
所以**升级后不需要为这次改动单独重启**：`restart.ps1` 是每次点击按钮时按路径现场调用的
（`index.js:21` 的 `SCRIPT_PATH` 拼接 → `conhost -File`），不是启动时加载的。

## 回退

回到 1.0.1：

```
plugin --profile desktop add https://codeload.github.com/csuwzw/dsh-restart/tar.gz/refs/tags/v1.0.1
```

或者移除 `dsh.profile.bundles` 里的 `dsh-restart`、从 `dependencies` 移除同名条目、删除
`node_modules/dsh-restart/`，然后重启应用一次。

回退只影响日志判读——1.0.1 的实际重启功能是正常的，只是它会把成功的重启报成
`listening=False`。

## 已知边界

- **仅 Windows。** 未在 macOS / Linux 上测试，`restart.ps1` 依赖的 WMI、`conhost.exe`、`taskkill`
  在那两个平台上都不存在。
- **判定窗口 30 秒。** 新实例启动超过 30 秒时脚本只写日志、不重试。有意不做重试：旧实例已被
  终止时盲目重试会造出重复实例。
- **未测过非默认 profile 名。** 参考实机为 `desktop`。
- **客户端产物改动需重启才生效。** 本 profile 未启用 `@deepseek-ai/dsh-client-hmr`；本版没有
  客户端改动，这一条不影响。
- **`github:` 简写依赖 git 这件事没有做代码层面的规避。** 本插件不改 pnpm 行为，只在文档里
  给出可用写法。
