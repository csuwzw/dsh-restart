# dsh-restart 1.0.0

首个发布版本。

## 本次更新

- **标题栏「重启」按钮。** 装在「应用 / 编辑」右侧，样式由 preload 造菜单条时留下的 open shadow
  root 里的裸 `button` 规则提供，因此高度、内边距、hover 背景与相邻菜单项天然一致；文案跟随
  `<html lang>` 切换中英。
- **两次点击才动手。** 第一次点进「确认重启？」态，4 秒内不点自动撤销；第二次点才发请求。按钮
  位置太顺手，而重启会终止正在运行的任务，所以加了这一层。
- **不弹控制台窗口。** 重启脚本整条命令包在 `conhost.exe --headless` 里。默认终端为 Windows
  Terminal 时它会忽略 `-WindowStyle Hidden`，脚本跑在可见窗口里，新实例继承该控制台后窗口被日志
  一直占着不会消失，手动关掉还会连带杀掉新实例——实测三种启动方式的控制台窗口数为 2 / 0 / 0，
  取 0 的那个。
- **绕过 job object。** 从插件里普通 spawn 的进程与 Host 同属一个 job，旧实例一退出就被一并带走。
  重启脚本改由 WMI（`Win32_Process.Create`）创建，父链是 `WmiPrvSE.exe → svchost.exe →
  services.exe`，已脱离该 job，且仍在 explorer 的交互会话里，因此能启动带界面的新实例。
- **以端口监听作为成功判据。** 日志四步齐全（`armed` → `taskkill` → `launched` → `verify`），
  最后一步等**新实例的 Host 子进程**重新监听，比数进程名可靠——`@deepseek-ai/dsh-subprocess-local`
  的 runner 子进程带同样的进程名，数进程会误报。
  （**2026-10-19 更正**：原文写的是「等 Host 重新监听端口」，那其实是等**旧实例**的端口，而桌面版
  固定以 `--port 0` 启动、端口由系统分配，所以该判据必然报 `listening=False`。判据已改为按新实例
  判定，详见 [验收记录第七节](../verification/2026-10-17-v1.0.0.md)。）
- **端口不硬编码。** 脚本的 `-Port` 取自请求连接的本端端口（`req.socket.localPort`），因为
  webServer 的端口可以配成 0 由系统分配。
- **仅回环可达的路由。** 以对端 socket 地址判定回环（Host 头是调用方可控的，只作附加检查），并
  要求自定义动作头 `x-dsh-restart-action`——这会把请求变成非简单请求，外部页面无法在不触发 CORS
  预检的情况下构造它。
- **零依赖、无构建步骤。** 宿主端只 import `node:` 内置模块；浏览器端是手写的 `__ModuleLoader__`
  bundle，不经打包器。不改内核，不留补丁。

## 安装

需要 DeepSeek Harness 桌面版（Windows），内核 `0.2.0-rc.2` 上验证通过。

桌面版自带一个能管理 `desktop` profile 的 CLI——`@deepseek-ai/dsh-desktop-host/lib/cli.js` 以
`manageDesktopProfile: true` 启动内核启动器，绕过了「desktop profile 由 Electron 独占管理」这道
闸门：

```
set ELECTRON_RUN_AS_NODE=1
"C:\D\software\DeepSeek Harness\DeepSeek Harness.exe" --expose-internals ^
  "C:\D\software\DeepSeek Harness\resources\app.asar\dsh\node_modules\@deepseek-ai\dsh-desktop-host\lib\cli.js" ^
  plugin --profile desktop add https://codeload.github.com/csuwzw/dsh-restart/tar.gz/refs/tags/v1.0.0
```

把路径换成自己的安装目录。用 codeload tarball URL 而不是 `github:csuwzw/dsh-restart`——后者会让 pnpm 跑
`git ls-remote` 解析 ref，机器上没有 git 就失败（详见 [PACKAGING.md](../../PACKAGING.md) 第四节）。其余安装方式
（应用内插件管理器、手工放置、离线 tgz）见 [README](../../README.md#安装)。

**首次安装必须手动重启一次 DSH**——按钮要等重启后才存在。之后就用按钮本身。

## 升级与重启

升级即重新执行上面的安装命令（或走应用内插件管理器）。装完点标题栏的「重启」按钮；按钮不存在时
从托盘退出应用再双击图标。

宿主端与客户端产物的改动都要重启才生效：宿主端本身是启动时挂载的；客户端 bundle 由
`@deepseek-ai/dsh-client-modules` 在启动 compose 时一次性读入并缓存，只有启用
`@deepseek-ai/dsh-client-hmr` 时才有 watcher 刷新，而本插件不引入 HMR。

## 回退

移除 `dsh.profile.bundles` 里的 `dsh-restart`，再从 `dependencies` 移除同名条目，删除
`node_modules/dsh-restart/`，然后重启应用一次。

插件不留补丁：它不写 profile 的 `cordis.patch.yml` / `cordis.yml`，只声明自己的 patch 层；也不
写注册表、不装服务、不建计划任务。日志文件 `$DSH_HOME/logs/dsh-restart-plugin.log` 为纯文本，
可直接删除。

## 已知边界

- **仅 Windows。** 重启脚本依赖 WMI、`conhost.exe` 与 `taskkill`，其它平台都没有。
- **未测过 webServer 端口配成 0 的部署**，也未测过非 `desktop` 的 profile 名。
- **没有重启失败的自动重试**：旧实例已被终止的情况下盲目重试会造出重复实例，因此有意不做。
- **按钮位于标题栏菜单条而非原生菜单内。** 那条原生菜单由 Electron 主进程用 `applicationItems()`
  构建，IPC handler 强制校验 sender，插件无法往里加项。
